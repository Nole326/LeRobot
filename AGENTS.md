# Integration repository rules

- Publish source code and generic documentation only. Keep course documents, reports, server inventories, validation outputs, screenshots, credentials and machine-local config private.
- Explicit publication exception (2026-10-02): the owner-approved bilingual project poster with contact information/page numbering removed, and a generic course-project introduction may be public. This does not authorize publishing the original poster, course PDF, private records or identifying contact details.
- GPU/installation/training/simulation/hardware actions need applicable authorization and compliance with destination rules. Use the approved task-specific container; never alter host drivers or other healthy tasks.
- Preserve upstream baselines and licenses; prefer external adapters. Record intentional patches and regenerate audited manifests. Do not silently change formal evaluation/controller rules.
- The nested IsaacLab dependency is expanded into ordinary files; keep it consistent with the canonical baseline unless explicitly patched.
- Diagnostic scripts are not evidence of successful training, formal task compatibility or complete simulator-state restoration.
- Never upload credentials, private keys, tokens, .netrc, private datasets or deployment records. Review staged contents and history before publishing.
- New training must validate matching model/optimizer/counters/data/replay/RNG checkpoints; a seed alone is not sufficient.
