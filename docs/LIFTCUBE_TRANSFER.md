# 从LiftCube到多物体抓放

LiftCube用于先打通数据、视觉策略、训练和部署。后续正式环境到位后，在同一训练管道中迁移模型；LiftCube成功率与完整抓放成功率分开报告。

SO101与配套环境的观测、控制、单位及时序适配可独立验收，无需先训练LiftCube策略。本页描述后续训练路线，执行范围由具体开发任务确定。

## 分阶段开发

1. **LiftCube**：核对数据，训练图像＋本体的BC/小型VLA；完成闭环抓取抬升、失败分析和基础RL对照。
2. **完整仿真**：接入指定物体、目标表达及正式评分；收集接近、抓取、转移、释放、撤离等完整轨迹，再做任务微调和RL。
3. **真机**：先按课程接口做不运动的输入/单位/延迟检查，随后按安全流程补少量真实演示、适配和评测。仿真训练不能替代真机标定。

当前只有cube任务，不能凭它证明不同形状/材质泛化，也不把自行扩展的场景称作课程正式环境。视觉、动作/频率、归一化及数据来源随每个模型一起保存。

## ACT和VLA怎样接续

| 内容 | ACT | VLA |
| --- | --- | --- |
| LiftCube阶段 | 学习图像＋关节条件下的抓取抬升动作chunk | 从合规预训练/适配权重开始，用LiftCube示范做任务SFT |
| 完整任务阶段 | 用原策略初始化，继续训练完整抓放轨迹；多目标时接入课程发布的目标条件 | 保留基座与适配配置，用完整任务图像、本体、任务条件和动作继续微调 |
| 可复用部分 | 视觉编码器、本体编码及相容的动作解码器 | 视觉语言表征、相容的机器人动作表示、部分任务技能 |
| 不能自动获得 | 指定物体识别、目标选择、放置与纠错能力 | 新任务的动作语义、未见物体稳定操作、语言指令与目标区的可靠对应 |

无需预先训练两个互不相干的模型，也不必现在做两个独立控制器的硬切换。ACT本身不会因新增一句提示词就获得语言理解：多目标条件需显式输入并在新数据上训练。VLA也必须按其实现接入官方任务条件，不从仿真物体ID/坐标制造策略输入。

如果后续仍是front图像＋六电机关节目标，优先复用策略权重、增加完整轨迹后继续微调；检查新数据统计、任务条件和动作chunk时长。若接口变成受限末端动作、相机或动作单位发生变化，先更新适配器和动作表示；不能只改输出维数或给关节动作换一个字段名。

LiftCube和完整任务应使用独立实验/存档：**前一阶段导出权重→新任务初始化**，不是把旧优化器、RL replay和计数照搬成“恢复”。是否继续Adam/适配器状态须在实验方案中显式定义，默认新任务使用新优化器。任务条件结构变化时，复用相容模块，新增头单独训练；统计、模型结构和加载差异留档。

为抑制遗忘，可将少量LiftCube数据与完整任务数据混合训练，比例先在训练/验证集选择。比较“从原基座直接适配完整任务”和“先LiftCube再适配”时，说明额外数据与计算预算；不得把多用数据的收益直接归因于迁移方法。RL优先从完整任务上已经可靠的BC/VLA开始。

### 模型接线与迁移边界

- ACT：front图像编码＋q编码＋显式任务/目标条件→Transformer动作解码器→动作chunk→课程执行与安全层。目标条件按正式接口实现；标准ACT不自动具备语言条件能力。
- VLA：front图像＋语言/任务条件＋许可本体→预训练视觉语言模块与动作模块→动作chunk→同一执行与安全层。微调全参数还是LoRA取决于所选后端，不预先固定。
- 抓取抬升阶段可提供视觉特征、手眼协调、关节到动作的映射及部分接近/闭合技能；多物体辨别、不同形状抓点、目标区定位、搬运、释放、撤离和恢复仍需新数据与评测。
- 完整任务公布后，新建实验、加载相容权重、重新核对统计与任务条件，使用完整抓放轨迹微调；默认新优化器。不要将只会抬红块的checkpoint直接当作已具备多物体泛化的策略。

当前实现仍是SmallCNN参考训练基础，不把上述ACT/VLA设计路线标成已接入或已训练。LiftCube足以验证训练、保存、加载与基本闭环后即可转向完整任务，不必等单一红块任务达到极限成绩。

## 专家演示获取路径

| 方法 | 可复用内容 | 仍需我们完成 |
| --- | --- | --- |
| 公开数据 | 当前候选[H2Ozone/lift_cube](https://huggingface.co/datasets/H2Ozone/lift_cube) | 来源、单位、标定、RGB/动作时序及成功性；有字段不等于可直接训练 |
| 人工遥操 | LeIsaac主从臂、键盘/手柄及录制器 | 少量高质量种子与纠错示范、独立成功复核，不全靠手工扩大规模 |
| MimicGen | 官方有LiftCube示例流程，含IK转换、子任务标注、生成和转回关节动作 | 可靠原始HDF5、任务配置、物体位姿/阶段标注与动作重放验收 |
| 程序化教师 | 复用环境、IK、轨迹生成与记录器 | 实现LiftCube的接近/闭合/抬升及失败处理；验证可达性和执行器协议 |
| 学习策略采集 | 经验证的任务ACT/VLA/RL模型＋同一记录格式 | 先实测成功率；成功与失败均留统计，合格轨迹才作为BC候选 |

推荐先获得少量可靠的同环境种子，验证MimicGen扩增；必要时补一个小型LiftCube教师。已有数据动作标定不明时，不从猜测零位、裁剪标签或放宽物理限位开始。

### 官方脚本与版本

[遥操录制](https://lightwheelai.github.io/leisaac/docs/getting_started/teleoperation/)和[动作重放](https://lightwheelai.github.io/leisaac/docs/getting_started/dataset_replay/)可以复用，不需要自己重写整个录制系统。配套v0.1.2镜像实际包含：

```text
scripts/environments/teleoperation/teleop_se3_agent.py
scripts/environments/teleoperation/replay.py
scripts/mimic/eef_action_process.py
scripts/mimic/annotate_demos.py
scripts/mimic/generate_dataset.py
scripts/convert/isaaclab2lerobot.py
```

[MimicGen文档](https://lightwheelai.github.io/leisaac/docs/features/mimicgen_env/)以LiftCube说明流程，但页面“示例数据”链接实际指向PickOrange数据，不能直接称为现成LiftCube种子。仅有LeRobot视频/关节表也不一定具备MimicGen所需的初态、物体变换和阶段信息。

[新版状态机入口](https://lightwheelai.github.io/leisaac/docs/features/state_machine/)存在，但当前上游`generate.py`的任务注册只有PickOrange，配套旧镜像没有该入口。LiftCube自动教师仍需新增任务逻辑/兼容适配；不升级整个课程环境来迁就该脚本。该上游入口还会修改机器人重力设置，不能原样当作课程固定物理协议。

另有[IsaacLab v2.1.1抬方块状态机](https://github.com/isaac-sim/IsaacLab/blob/v2.1.1/scripts/environments/state_machine/lift_cube_sm.py)，包含接近上方、下降、抓取、抬升，可参考流程；它针对Franka并读取物体真实位姿，不是可直接用于SO101的无特权视觉基线。

### 视觉几何/规则对照

传统基线不要求把整套机器人算法从零实现。可复用OpenCV检测与[平面标定/单应变换](https://docs.opencv.org/4.x/d9/dab/tutorial_homography.html)，结合许可关节位置和课程运动接口，补齐任务状态机。基础路线为：RGB检测指定物体/目标→标定下的桌面定位→接近/下降/闭合/抬升/搬运/释放。单应关系只对指定平面成立，物体高度、遮挡和不同形状要单独处理，不能将所有像素点当作准确三维抓点。

供采集种子的真值教师与正式视觉规则基线共用运动原语，但感知来源、评测和记录分开；前者不能冒充后者。当前尚无我们验收通过、能直接用于课程SO101 LiftCube的完整视觉规则脚本。

镜像内遥操、重放和Mimic标注代码出现动态夹爪辅助调用。使用前核对具体开关、辅助函数及机器人类型分支；不能预先把原生采集栈标成固定执行器或无特权。辅助数据单独标注；要形成课程固定协议演示，须在对应执行器条件下重放验收，不将辅助状态送入策略。人工N键标签也不能代替原生任务成功复核。

### 数据统一与筛选

- 保留原始记录，再导出ACT/VLA需要的格式。记录来源/teacher、任务、初态/seed、前RGB、关节位置、请求与实际动作、时间戳/保持tick、终态和成功信号。
- 策略输入只包含许可观测。仿真真值可按课程许可用于教师规划、标注和训练奖励，但与训练输入隔离；程序化数据是否替代遥操交付另向课程确认。
- 30Hz决策数据应记录真实两tick保持；从60Hz任意丢掉隔帧动作，不一定等价于30Hz执行。先核对采集控制周期和实际命令，再转换。
- 按完整轨迹、场景和物体拆分，扩增的同源种子不跨训练/验证/测试。不要按帧随机划分，也不只报告成功采集尝试。
- 优先检查动作范围/连续性、图像时间同步、掉落/滑移、原生成功；代表性原动作重放验证执行，不用状态回放冒充闭环可执行性。失败/纠错记录单独保留，不混称成功BC示范。

批量采集和正式训练在数据、控制及资源条件满足后启动。更多任务条件、物体集合、时间上限和正式测试集以课程后续发布为准。
