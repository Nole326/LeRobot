# 训练前验证 / Training validation

## 当前LiftCube与历史诊断 / Current LiftCube and legacy diagnostics

当前LiftCube训练入口及存档契约见[训练指南](../course/liftcube/TRAINING.md)，演示是否准入见[SO101验收](SO101_ACCEPTANCE.md)。参考BC/PPO覆盖合成CPU流程/恢复检查，环境交互另有实际短测；这些证据不等于公开演示已可训练或学得策略已完成任务。

For current LiftCube, follow the training guide and SO101 data-acceptance notes. Synthetic trainer/recovery tests and live environment-interface checks have different scopes; neither establishes accepted demonstration data or a successful learned policy.

[视觉规则基准](SCRIPTED_LIFTCUBE.md)不经过训练入口，无需执行下文ACT优化诊断；[末端开发层](PLANAR_EE_DEVELOPMENT.md)的三维控制和物理精度单独验收。以下20帧/双RGB工具属于较早的独立诊断，不是当前LiftCube训练命令。

The rule baseline bypasses training; its grasp results are not BC/PPO results. Validate planar-control accuracy separately. The dual-RGB, 20-frame tools below are legacy standalone diagnostics, not the current LiftCube trainer.

`course/scripts/training_contracts.py` 提供独立的末帧缓冲和随机数状态工具，不修改上游环境、奖励或策略实现。验证入口为 `validate_training_readiness.py`。

`course/scripts/training_contracts.py` provides independent final-observation and RNG-state utilities without modifying upstream environments, rewards or policies. The validation entry point is `validate_training_readiness.py`.

## CPU 验证 / CPU checks

在已配置 LeRobot 的隔离环境中运行，输出目录必须是新目录：

Run in an isolated LeRobot application environment, using a new output directory:

```bash
CUDA_VISIBLE_DEVICES="" HF_HUB_OFFLINE=1 python course/scripts/validate_training_readiness.py \
  --dataset-root /path/to/controlled-validation-dataset \
  --output /path/to/new-validation-output
```

此入口针对既有桥接工具生成的单回合、20帧、10Hz验证数据，包含双RGB与六关节状态；不是任意数据集的训练入口。只执行少量ACT优化步骤以检查数值和恢复，不输出任务成绩。存档只加载本次脚本生成且哈希核验通过的本地文件，不接受来源不明的 pickle 存档。

This entry point expects the existing bridge tool's one-episode, 20-frame, 10Hz validation dataset with dual RGB and six joint values. It is not a general dataset trainer. A few ACT optimizer steps test numerical behavior and recovery, not task performance. Checkpoints must be locally generated by this validator and hash-verified; do not load untrusted pickle artifacts.

验证内容包括：超时与真正终止的区别、向量环境末帧行映射、padding屏蔽、归一化存档、数据排列与游标、Python/NumPy/Torch及登记的独立随机流，以及新进程恢复后下一步损失、参数、优化器和学习率调度的一致性。

Checks cover timeout versus termination, vector-environment final-observation row mapping, padding masks, saved normalization, sample permutation and cursor, Python/NumPy/Torch and registered private RNG streams, and equality of the next loss, parameters, optimizer and scheduler after recovery in a fresh process.

## 接入边界 / Integration limits

末帧工具需要仿真端在自动reset前捕获真实图像和状态。CPU测试只能验证缓冲和转移语义，不能证明实际相机更新时序；reset返回的观测继续给下一回合策略，末帧单独用于上一条transition。

The final-observation utility requires the simulator to capture real images and state before auto-reset. CPU tests validate buffering and transition semantics, not actual camera timing. Reset observations feed the next episode's policy, while terminal observations belong to the preceding transition.

恢复测试限定单进程、CPU、零DataLoader worker；独立环境随机流使用占位生成器。CUDA随机流、多worker预取、仿真现场、RL replay和在线ACT缓存仍须分别验收。工具尚未接入正式训练入口，不能把这项测试当作正式训练可无缝恢复的证明。

Recovery checks use CPU, one training process and zero DataLoader workers; the private environment stream is a placeholder generator. CUDA RNG, worker prefetch, simulator state, RL replay and online ACT caches need separate validation. The utilities are not yet integrated into a production training entry point and do not establish seamless recovery of formal training.

正式训练都需要动作/观测、奖励与成功定义及端到端闭环验收。BC另外需要已确认成功性的演示和episode级划分；纯在线RL不必先取得演示，若采用BC初始化则须同时满足数据前提。上游PickOrange接口检查不能代替课程正式接口验收。

Training needs validated observations/actions, rewards, success criteria and an end-to-end policy loop. BC additionally requires accepted demonstrations and episode-level splits; online RL need not use demonstrations unless initialized from BC. PickOrange interface checks do not substitute for formal task acceptance.
